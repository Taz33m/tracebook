# Tracebook 0.7.3

A FIFO qualification packet now has to agree with workloads regenerated by
the verifier. Tracebook checks fixed-case configuration, compared-event counts,
terminal order-book hashes and generated trace identities. It also replays the
workload to verify the claimed capability coverage.

This release addresses 25 reliability priorities with 55 regression cases that
failed against 0.7.2. Other changes include the following.

- Matching-engine and L3 reductions keep the original execution or rejection
  difference. A candidate whose reported order count contradicts its snapshot
  produces a protocol error. An adapter crash fails semantic reproduction.
- CSV and JSONL replay read one record at a time. Ambiguous order records fail
  with an input error. Report writers protect source traces and corpus evidence.
- Coinbase normalization checks snapshot product identity and decimal fidelity.
  Skipped invalid messages preserve resting orders and the exchange trade ledger.
- Benchmark comparison checks reported throughput and elapsed time against the
  underlying samples, workload size and phase inventory.

Both packages use version 0.7.3. Recreate qualification packets to obtain IDs
with the new reference version. The four FIFO controls are the historical Flash
workload, the seeded partial-fill and replacement cases, and competing fills.

## Installation

For an existing environment containing the legacy 0.5.x simulator, remove its
package ownership before installing either distribution.

```bash
python -m pip uninstall -y tracebook-sim
```

Install the lightweight package and run the historical proof from an empty
directory with rustup, Rust 1.88.0, a native linker and access to Cargo dependencies.

```bash
python -m pip install "tracebook-conformance==0.7.3"
tracebook-conformance fifo-proof
```

The simulator facade installs the exact matching conformance package.

```bash
python -m pip install "tracebook-sim==0.7.3"
```
