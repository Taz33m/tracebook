# Tracebook 0.6.0: Lightweight Qualification, Honest Contracts

Version 0.6.0 makes matching-engine qualification independently installable
without changing the `tracebook` import namespace or transferring adapter
ownership to candidate maintainers.

## Install Matching-Engine Qualification

If this environment contains `tracebook-sim` 0.5.x, remove that legacy package
owner before installing either 0.6.0 distribution:

```bash
python -m pip uninstall -y tracebook-sim
```

```bash
python -m pip install "tracebook-conformance==0.6.0"
```

This distribution owns the `tracebook` package, immutable suite fixtures,
typing marker, and `tracebook-conformance` command. It has no mandatory runtime
dependencies. The release smoke runs a complete `fifo-limit-v1` qualification
in a clean environment with neither NumPy nor psutil: 3/3 fixed cases, 25/25
generated traces, 5,000 events, and 10/10 semantic capabilities.

Install the compatibility facade when you need simulation, benchmarks,
profiling, visualization, replay, corpus tooling, or their optional extras:

```bash
python -m pip install "tracebook-sim==0.6.0"
```

The facade owns no importable package. It depends on the exact matching
`tracebook-conformance` release plus NumPy and psutil and preserves the seven
non-conformance console scripts.

## Required 0.5.x Migration

Do not directly upgrade an environment containing `tracebook-sim` 0.5.x. The
old distribution owns the same package paths that move to
`tracebook-conformance` in 0.6.0, so its uninstall record can remove newly
installed files.

Use the supported uninstall-first handoff:

```bash
python -m pip uninstall -y tracebook-sim
python -m pip install "tracebook-sim==0.6.0"
```

For conformance only, install `tracebook-conformance==0.6.0` in the second
command. If an attempted direct upgrade already damaged the environment:

```bash
python -m pip install --force-reinstall --no-deps "tracebook-conformance==0.6.0"
python -m pip check
```

The two 0.6.0 wheels have disjoint RECORDs. This warning is for the one-time
handoff from the monolithic 0.5.x owner.

## Contract Corrections

- Semantic disagreements exit `1`; configuration, adapter, protocol, process,
  and filesystem failures consistently exit `2`.
- Minimization and reproduction JUnit reports fail on nested operational
  failures instead of projecting green.
- A candidate shutdown error no longer overwrites the first semantic
  divergence; it is retained as auxiliary `close_error` evidence.
- CI documentation describes JUnit as an uploaded result projection unless a
  separate reporter consumes it.
- Qualification artifact publication is supported and release-tested on
  Ubuntu, not claimed as operating-system independent.

## Coordinated Release Integrity

The release workflow builds and validates both distributions from the same tag,
rejects version drift and overlapping file or entry-point ownership, rebuilds
both wheels from their sdists, performs a resolver-driven clean simulator
install, and exercises the uninstall-first migration against the
SHA-256-pinned public 0.5.0 wheel. Commit-derived timestamps and pinned build
backends make wheel bytes reproducible if a partial publication must be
retried. The workflow publishes `tracebook-conformance` before
`tracebook-sim`; the facade is not published until the exact conformance wheel
is available from PyPI and matches the built artifact.

## Adoption Boundary

The packaging work removes unrelated installation weight; it does not enlarge
the maintainer ask. Tracebook's narrow loop remains:

1. discover or receive a raw semantic discrepancy;
2. localize it and reduce it to reviewable evidence;
3. translate that evidence into a small native regression for maintainer
   review; and
4. add adapter or CI ownership only after the maintainer has seen concrete
   value and chooses to retain it.

PRs or campaigns run only by the Tracebook repository remain technical
evidence, not independent adoption.
