# Tracebook 0.7.0: Captured Evidence And Separate Book-Replay Contracts

**Draft — not published.** Both distribution versions are prepared as 0.7.0.
No release date, public tag, PyPI upload, or independent adoption outcome is
claimed by this document. Public 0.6.0 remains the install target until release.

## Release Scope

- Captured two-run qualification: candidate identity checks, clean evidence
  roots, and `evidence-init` / `evidence-verify` for complete, unchanged,
  byte-identical qualification bundles.
- A separate `l3-book-replay-v1` contract for market-data add/update/delete
  events and non-mutating FIFO fill probes. It includes a pinned optional
  NautilusTrader adapter, deterministic generated campaigns, reduction, and a
  retained injected queue-priority negative control. This is not a submitted-
  order matching-engine contract or a claim about Nautilus's fill simulator.
- A pinned native Go adapter for `intrepidkarthi/orderbook`, with FIFO-limit
  and partial-fill qualifications. The retained unfillable-FOK example is a
  contract difference, not an upstream defect claim.
- Checked native Rust quantity encoding: output display precision no longer
  rounds order, reduction, or replacement input before matching. Inputs must
  fit the adapters' exact 12-place integer domain; this is not a claim of
  unrestricted precision equivalence with a binary-floating-point engine.
- Stricter stdio shutdown and no-clobber L3 report/reduced-trace publication.
  Existing output paths now fail before candidate execution. New complete
  artifacts publish individually, with reduced traces before reports; abrupt
  interruption is not a cross-file atomic transaction.
  If the first staging-directory identity read fails, the CLI reports possible
  residue and exits before starting a candidate. Unverified entries are kept;
  [manual recovery](../book-replay-conformance.md) requires independently
  confirmed ownership, not blanket deletion of staging paths.
- Distribution privacy gates, clean-install/migration checks, and native CI
  trigger coverage for the reference/runtime code those integrations execute.

The corrected 24-run research aggregate is included in the source record:
1/12 safe passes with public documentation versus 5/12 with the frozen skill.
That improvement was confined to boundary judgment; neither arm safely
qualified the compatible engine. Frozen protocols, historical evidence,
private gold, and evaluator artifacts are not revised for this release.
The 13 frozen-harness review findings remain explicitly deferred in
[issue #85](https://github.com/Taz33m/tracebook/issues/85). Merging the
release-code fixes does not fix or dismiss those research findings.

## Install After Publication

These commands are future post-publication instructions, not available package
downloads today. If an environment contains the monolithic `tracebook-sim`
0.5.x, first uninstall that legacy owner:

```bash
python -m pip uninstall -y tracebook-sim
```

For the dependency-light conformance commands:

```bash
python -m pip install "tracebook-conformance==0.7.0"
```

For simulation, replay, benchmarks, and the other workbench commands:

```bash
python -m pip install "tracebook-sim==0.7.0"
```

The facade remains package-less and pins the exact conformance version. Its
seven console scripts and the conformance command keep their distribution
ownership. Python 3.10–3.13 is the supported package matrix; the optional
Nautilus 2.0.0rc3 integration is separately exercised on Python 3.14 and is not
a mandatory package dependency. Native adapters remain out of process.

The L3 entry point is `python -m tracebook.book_replay`; no new console script
is claimed. See [book-replay conformance](../book-replay-conformance.md) and
[captured onboarding](../independent-onboarding.md) for the exact workflows.

## Evidence Compatibility

Existing profile names, generator versions, suite hashes, trace bytes, and
retained failure controls keep their meaning. A qualification ID covers the
full report, including reference-engine version metadata, so a fresh 0.7.0
qualification can have a different ID from an otherwise equivalent 0.6.0 run.
Do not relabel old artifacts or rewrite frozen experiment evidence. The sent
maintainer invitation remains pinned to its tested pre-release source revision
and wheel hash; a release-based attempt is new evidence.
